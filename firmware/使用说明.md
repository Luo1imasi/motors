# 固件升级脚本（firmware_flasher.py）使用说明

## 1. 简介

`firmware_flasher.py` 是一个**单文件** Python 固件升级脚本，通过广成
USBCANFD 适配器向 CAN 总线上的设备烧录固件。适合集成到您自己的
Python 产品中，也可以直接命令行使用。

核心特性：

- 单文件交付，仅依赖 Python 标准库，无任何第三方 pip 依赖
- 同步阻塞模型，接口简单，多台设备循环烧录只需一个 `for` 循环
- 烧录全流程自动完成：连接 → 擦除 → 逐块写入 → 设备自校验 → 复位重启
- 全中文错误消息与日志

## 2. 文件清单

| 文件 | 用途 | 是否必需 |
|------|------|---------|
| `firmware_flasher.py` | 升级脚本本体 | 必需 |
| `ECANFDVCI64.dll` | 适配器运行库（上层） | 必需 |
| `GCANUSB_x64.dll` | 适配器运行库（底层） | 必需 |
| `MSVCR120.dll` | VS2013 运行时库 | 必需 |

三个 DLL 请与 `firmware_flasher.py` 放在**同一目录**（脚本按自身所在
目录查找，与您从哪里运行无关）。

## 3. 运行环境要求

- Windows x64
- Python 3.8 及以上，**64 位**版本（32 位 Python 无法加载 x64 运行库）
- 广成 USBCANFD 系列 USB 适配器
- 适配器内核驱动已安装（每台电脑安装一次；如未安装，请向适配器
  供应商获取驱动安装包，插上适配器前运行 `DPInst64.exe` 完成安装）

## 4. 快速开始（命令行）

接好适配器与设备，设备断电后重新上电，然后：

```
python firmware_flasher.py 固件文件.bin --can-id 0x1001
```

- `固件文件.bin`：固件文件路径（原样写入设备，不做任何格式转换）
- `--can-id`：目标设备的 CAN ID（必填，支持 `0x` 十六进制写法）

成功时的输出：

```
写入进度: 100%
升级完成
```

设备 ID 规则：总线上第 i 台设备的 ID 为 `0x1000 + 2*i - 1`
（第 1 台 `0x1001`，第 2 台 `0x1003`，第 3 台 `0x1005`，以此类推）。
设备应答 ID 由脚本自动处理（请求 ID + 1），无需配置。

## 5. 集成到您的产品（Python API）

### 5.1 单台设备（最简）

```python
from firmware_flasher import update_firmware

update_firmware(r"D:\fw\app.bin", can_id=0x1001)
```

失败时抛出 `FlashError` 子类异常（见第 8 节）。

### 5.2 多台设备循环烧录（推荐）

适配器只打开一次，循环烧录多台，单台失败不中断后续：

```python
from firmware_flasher import FirmwareFlasher, FlashError

with FirmwareFlasher() as flasher:
    for can_id in (0x1001, 0x1003, 0x1005):
        try:
            flasher.flash(r"D:\fw\app.bin", can_id=can_id)
            print(f"0x{can_id:X} 升级成功")
        except FlashError as e:
            print(f"0x{can_id:X} 升级失败: {e}")
```

### 5.3 进度回调

```python
def on_progress(written, total):
    print(f"{written}/{total} ({written * 100 // total}%)")

update_firmware("app.bin", can_id=0x1001, on_progress=on_progress)
```

回调按写入块粒度调用（每 256 字节一次），刷新 UI 请自行节流。

### 5.4 超时调整（一般不需要）

默认超时即实机验证的推荐值。特殊场合（如超大固件擦除偏慢）可只改
单个字段：

```python
from firmware_flasher import FirmwareFlasher, FlashTimeouts

flasher = FirmwareFlasher(timeouts=FlashTimeouts(erase_ms=15000))
```

| 字段 | 默认（毫秒） | 含义 |
|------|-------------|------|
| connect_ms | 500 | 连接响应 |
| connect_retries | 3 | 连接重试次数 |
| command_ms | 1000 | 常规命令 |
| program_start_ms | 2000 | 进入写入模式 |
| erase_ms | 10000 | 擦除 |
| verify_ms | 10000 | 设备自校验 |
| cf_gap_ms | 1000 | 多帧/流控帧间隔 |

### 5.5 日志接管

脚本默认不输出日志。需要时用标准 `logging` 接管（logger 名
`firmware_flasher`）：

```python
import logging

logging.basicConfig(level=logging.DEBUG,
                    format="%(asctime)s %(levelname)s %(message)s")
```

`DEBUG` 级输出每块写入进度；更底层的逐帧收发字节日志为 `TRACE` 级
（数值 5，低于 DEBUG），排障时使用：

```python
logging.basicConfig(level=5, format="%(levelname)s %(message)s")
```

## 6. 总线与设备参数（固定值）

以下参数与设备出厂配置一致，由脚本内部自动设置，无需（也不支持）
修改：

| 参数 | 值 |
|------|-----|
| 帧类型 | CANFD，BRS 加速 |
| 仲裁段波特率 | 1 Mbps |
| 数据段波特率 | 5 Mbps |
| 帧格式 | 扩展帧 29 位 ID |
| 写入起始地址 | 0x60000000 |
| 单块写入大小 | 256 字节 |

**适配器型号要求**：仅支持 USBCANFD 系列适配器；经典 USBCAN2
（不带 FD）不适用。

## 7. 升级流程说明

脚本对单台设备依次完成以下步骤（全自动，无需干预）：

1. **连接**：向设备发送连接命令（无响应时自动重试 3 次）
2. **握手与进入写入模式**
3. **擦除**：按固件大小擦除设备存储区
4. **逐块写入**：固件按 256 字节分块依次写入，每块成功后触发进度回调
5. **设备自校验**：设备端回读校验写入内容
6. **复位**：设备自动重启运行新固件

## 8. 错误类型与排查

所有失败都抛 `FlashError` 的子类，`str(e)` 为中文描述：

| 异常 | 含义 | 处理建议 |
|------|------|---------|
| `AdapterError` | 适配器打开/初始化失败 | 检查 USB 连接；确认三个 DLL 与脚本同目录 |
| `ConnectError` | 设备连接失败 | **将设备断电 5 秒后重新上电再试**（见第 9 节） |
| `CommandError` | 设备返回错误（附错误码） | 按错误码含义处理，如「设备写入失败 (0x31)」多为固件文件与设备不匹配 |
| `FlashTimeoutError` | 等待设备响应超时 | 检查总线接线；确认设备已上电 |
| `VerifyError` | 设备自校验未通过 | 重试；仍失败则联系固件供应商 |
| `FirmwareFileError` | 固件文件读取失败 | 检查路径与文件是否可读、非空 |
| `TransportError` | 总线多帧传输异常 | 检查总线干扰；开启 TRACE 日志定位 |

命令行方式失败时，错误消息直接打印在控制台，进程退出码非 0。

## 9. 重要注意事项

1. **设备断电重上电后才能再次升级**。设备在一次连接后进入升级态，
   不会响应重复的连接请求——每次升级前（包括升级失败后重试前），
   请先将设备断电约 5 秒再重新上电。多台设备各自独立，互不影响。
2. **固件文件原样写入**：脚本不解析、不转换固件内容，请使用设备
   固件供应商提供的文件。
3. **同步阻塞**：升级期间（数千字节到数兆字节，视固件大小数秒到
   数分钟）调用线程阻塞。需要异步请自行放入后台线程。
4. **一台适配器一次升级一台设备**：多台设备用 CAN ID 区分，
   逐台进行。
5. 升级过程中请勿断开适配器或设备电源，避免写入中断。

## 10. 常见问题

**Q：升级成功后设备没重启？**
A：脚本最后一步发送复位命令后即返回，设备复位是异步的，请等待
1-2 秒后观察设备状态。

**Q：换了一台电脑跑不起来？**
A：新电脑需要装 USBCANFD 内核驱动（见第 3 节），并确认 Python 是
64 位。

**Q：能同时烧多台吗？**
A：通过 CAN ID 逐台循环烧录（见 5.2 节），同一时刻只与一台设备
通信。
